# 需求文档

## 1. 应用概述

### 1.1 应用名称
全站异步并发抓取通用框架控制台

### 1.2 应用描述
一款基于极客终端风格的异步全站资源采集与存储Web控制台，支持终端命令行与可视化交互双模式操作。具备多引擎实例并行管理与生命周期调度、域名级请求间隔与抖动防封禁、内存与持久化队列切换、多种解析器组合使用、字符集自动识别转码、多媒体及文档资源分类存储、磁盘下载目录清理管理，并支持多套预设主题切换与自定义背景设置。

## 2. 用户与使用场景

### 2.1 目标用户
需要进行批量多任务数据采集、网站静态资源归档、网页内容结构化解析，偏好终端命令行交互及对界面视觉有定制化需求的开发与运维人员。

### 2.2 核心使用场景
- 多任务并发采集与实例管控：在控制台创建并管理多个并发抓取引擎实例，分别查看各实例卡片监控指标与全局聚合看板，支持状态过滤、关键词搜索、独立或批量启停与断点续爬。
- 智能防封禁抓取：针对目标站点配置域名级请求间隔与随机抖动，保证同域名请求节律自然且不同域名并发互不阻塞。
- 命令行高效交互：通过终端输入指令（含Tab自动补全）快速执行多引擎管理、服务启停、URL导入与磁盘清理。
- 大规模断点续爬：使用持久化队列边发现链接边写入，支持针对指定引擎实例中断后继续执行，或在停止/失败卡片上一键触发续爬。
- 多格式与多类型资源归档及管理：自动识别页面编码，自动分类下载并实时统计图片、视频、文档等真实资源数据，支持按分类或全量执行磁盘清理释放空间。
- 界面个性化定制：在极客终端暗绿、简洁亮色、深空蓝等预设主题之间快速切换，或自定义背景壁纸。

### 3.2 功能说明

#### 3.2.1 任务看板与状态统计模块
- 状态指标真实统计：看板展示待抓取、处理中、已完成、失败、已下载资源总量等全局聚合指标，初始值均为0，实时汇总所有引擎实例数据。
- 真实QPS指标计算：QPS（页面/秒）基于当前所有运行中引擎实例抓取的总页面数与实际运行时长进行动态计算；无任务运行时明确显示为0。
- 引擎列表工具栏：
  - 状态过滤按钮组：提供「全部 / 运行中 / 已完成 / 已停止 / 失败」多项切换，每项展示对应的实时实例计数徽标，选中态高亮。
  - 关键词搜索框：支持按域名、种子URL、引擎ID、续爬来源关键词进行前端模糊匹配过滤，提供一键清空按钮。
- 并行引擎实例卡片列表：位于任务看板/状态指示区与抓取控制台Tab中，支持随系统定时轮询自动刷新，包含以下能力：
  - 布局与排序：采用网格布局，移动端单列展示，桌面端双列展示；卡片统一等高设计。排序规则为处于 `running` 状态的卡片强制置顶，其余状态卡片按启动时间（started_at）倒序排列。
  - 卡片头部信息：等宽字体展示引擎唯一标识（engine_id）以及启动时间戳。
  - 运行时长与耗时展示：
    - 处于 `running` 状态时，展示脉冲时钟图标与「已运行 mm:ss / h:mm:ss」计时器，每秒动态递增。
    - 处于结束态（`finished`/`stopped`/`failed`）时，展示中性时钟图标与基于结束时间计算的「总耗时 mm:ss / h:mm:ss」。
  - 四态视觉状态标签：
    - `running`：主色高亮徽标配合呼吸脉冲动画圆点，卡片边框高亮呈现活跃状态。
    - `finished`：成功绿色徽标搭配完成状态图标。
    - `stopped`：中性灰色徽标搭配暂停状态图标。
    - `failed`：红色高警示徽标搭配警告状态图标。
  - 进度可视化：展示 `pages_crawled / max_pages` 计数，并提供进度条；处于 `running` 状态时进度条具备动画填充效果。
  - 参数摘要展示：结构化呈现任务参数快照，包含队列模式（memory/sqlite）、域名请求间隔、并发数、最大深度及目标域名列表（超长自动截断）。
  - 底部操作与状态提示：
    - 针对 `running` 状态卡片：底部提供「停止」操作按钮，点击终止该实例。
    - 针对 `stopped` 或 `failed` 状态卡片：
      - 若队列模式为 `sqlite`，底部提供「一键续爬」操作按钮，点击后触发对应实例的断点续爬。
      - 若队列模式为 `memory`，底部展示「内存队列引擎 · 不支持断点续爬」文本提示，不提供续爬按钮。
    - 针对 `finished` 状态卡片：底部展示「已完成 · 无需续爬」文本提示。
  - 空态与无匹配引导：
    - 当系统中无任何引擎实例时，展示整体空态引导文案，提示用户启动新引擎任务。
    - 当存在引擎实例但经过状态过滤或关键词搜索后无匹配结果时，展示「无匹配的引擎实例」并提供「清除筛选条件」操作按钮。

#### 3.2.2 任务配置与引擎调度管理模块
- 任务配置项：前端任务配置区提供目标URL输入、队列模式选择以及「域名请求间隔(秒)」配置项。
- 多引擎实例生命周期管理：
  - 启动实例：支持创建新抓取引擎实例，系统分配唯一engine_id并记录启动时间与参数快照。
  - 最大并行实例守卫：内置最大并行引擎数限制，若当前处于running状态的引擎数达到上限，拒绝创建并返回冲突错误提示。
  - 停止实例：支持按指定engine_id单独停止指定引擎，或一键停止全部运行中的引擎实例。
  - 断点续爬：支持指定engine_id恢复SQLite队列任务，未指定时默认作用于最近一个SQLite队列引擎实例。
  - 历史记录维护：引擎结束后记录ended_at并置为stopped、finished或failed，系统自动保留最近的历史引擎记录并自动清理过期实例。
- 域名级限速与抖动防封禁：
  - 调度器针对同一域名强制执行最小请求间隔控制，并在基础间隔上叠加随机时间抖动，避免固定请求节律。
  - 域名隔离：不同域名之间的请求独立调度，互不阻塞。

#### 3.2.3 队列管理模块
- 内存队列：支持一次性导入目标URL至当前引擎的内存队列中进行异步调度处理。
- SQLite持久化队列：提供基于SQLite的URL持久化队列，记录URL抓取状态，支持引擎异常中断或手动停止后的断点续爬。

#### 3.2.4 解析与提取模块
- 解析器实现：内置基于BeautifulSoup4、XPath(lxml)以及正则表达式(re)的三种解析实现。
- 解析器工厂与组合解析：支持全局配置、单个任务指定解析器以及对同一目标内容依次执行多级提取。
- 解密处理：提供统一的解密处理接口，支持在数据解析前后对加密内容执行预定义解密。

#### 3.2.5 资源下载与存储模块
- 字符集自动识别与转码：自动分析响应头及内容特征完成编码转换，保证中文文本无乱码。
- 资源真实分类统计：基于后端已归档的真实数据按分类目录实时统计展示，初始已下载列表为空。
- 资源分类存储：识别图片、视频、音频、文档、压缩包、代码、数据等文件类型，自动分类归档保存至downloads本地目录。
- downloads磁盘清理：支持在界面或通过指令触发全量清理或指定分类清理（含临时切片），执行后返回删除文件数与释放空间大小并刷新看板。

#### 3.2.6 任务调度与事件监听模块
- 观察者事件监听：定义任务生命周期事件，每条事件日志均携带来源engine_id，支持按引擎实例或全局回放事件日志。

#### 3.2.7 终端命令控制台模块
- 命令交互与Tab自动补全：支持命令名及参数选项（含引擎ID、队列类型、清理分类、主题等）的自动补全与历史回溯。
- 核心指令集：
  - `start [options]`：支持携带请求间隔参数启动新引擎实例并输出engine_id。
  - `stop [engine_id]`：停止指定引擎实例；未提供参数时停止全部运行中的引擎实例。
  - `status`：查看全局聚合运行指标及当前活跃引擎摘要。
  - `engines`：列出所有引擎实例的ID、状态、参数与进度信息。
  - `resume [engine_id]`：恢复指定SQLite引擎断点续爬，默认恢复最近一个持久化引擎。
  - `cleanup <category|all>`：清理downloads目录下指定分类或全部资源文件。
  - `serve`：触发后端服务拉起并轮询检测状态；不支持时输出手动启动指引。
  - `backend [url]`：查看或切换后端服务地址。
  - `help`：展示完整命令手册与参数用法。

#### 3.2.8 UI主题与个性化设置模块
- 预设主题：提供极客终端暗绿、简洁亮色、深空蓝等多套内置主题，支持一键切换。
- 自定义背景图片：支持本地上传或URL设置背景图片，并保持文字对比度适配遮罩。

## 4. 业务规则与核心逻辑

### 4.1 多引擎实例注册表与生命周期规则
1. 系统通过引擎实例映射注册表管理全部引擎对象，每个实例拥有唯一engine_id，生命周期状态包括：`running`（运行中）、`stopped`（手动停止）、`finished`（全部URL消费完成）、`failed`（执行异常中断）。引擎结束时记录结束时间戳（ended_at）。
2. 启动引擎时，系统首先校验当前处于`running`状态的引擎总数。若已达到最大并行实例上限，拒绝创建并返回错误提示；未达上限则实例化引擎并初始化状态为`running`。
3. 执行停止操作时：若传入特定engine_id，仅将对应实例置为`stopped`并释放其调度资源；若未传参，则遍历并将所有`running`状态的实例统一置为`stopped`。
4. 处于`finished`、`stopped`或`failed`状态的引擎实例保留在注册表中供查询历史状态，超出最大保留容量时遵循先进先出规则自动剔除旧记录。
5. 卡片列表排序规则：处于`running`状态的引擎卡片强制固定在列表最前列展示；其余非运行态引擎按`started_at`降序排列。
6. 断点续爬规则：仅对使用`sqlite`队列模式且状态为`stopped`或`failed`的引擎实例提供续爬入口。触发续爬后生成新的续爬引擎实例加入调度队列并刷新列表。

### 4.2 域名级限速与随机抖动规则
1. 限速作用域为目标URL的Host/域名。调度器维护各域名的最近一次请求时间戳。
2. 设任务配置的基础请求间隔为 `request_delay`（默认1.0秒），随机抖动范围为 `jitter`（0 ~ 0.5秒均匀随机分布）。
3. 同一域名连续两次请求之间的实际等待时长计算公式为：`actual_delay = request_delay + random(0, jitter)`。
4. 当待抓取URL的目标域名距离上次请求时间未满 `actual_delay` 时，调度器仅挂起该域名的请求协程，不阻塞其他不同域名的并发抓取任务。

### 4.3 指标计算与数据真实性规则
1. 系统初始化或无任务运行时，聚合看板指标全部归0。
2. 全局QPS = 当前所有处于`running`状态引擎所抓取的总页面数 ÷ 当前运行累计总耗时（秒）。所有引擎停止后QPS显示为0。
3. 资源统计严格依据后端downloads目录实际产生的文件按category进行真实计数。

### 4.4 磁盘清理与安全校验规则
1. 清理参数严格执行白名单校验（`images`、`videos`、`audios`、`documents`、`archives`、`code`、`data`、`others`、`all`），杜绝路径穿越风险。
2. 执行清理后返回删除文件数与释放字节数，并实时同步刷新聚合看板与资源分类列表。

## 5. 异常与边界情况

| 序号 | 异常/边界场景 | 表现与处理规则 |
| :--- | :--- | :--- |
| 1 | 启动新引擎时已达最大并行实例上限 | 拒绝创建实例，返回提示当前并行任务已满，展示正在运行的引擎列表 |
| 2 | 执行 `stop` 或 `resume` 时传入不存在的 engine_id | 提示指定的 engine_id 不存在，输出当前有效引擎列表供用户选择 |
| 3 | 执行 `resume` 未传参但不存在历史 SQLite 队列引擎 | 提示当前无可用断点续爬的持久化引擎实例 |
| 4 | 前端发起抓取时后端服务未启动 | 提示后端未运行，引导用户在终端执行 `serve` 命令启动后端服务 |
| 5 | 执行 `serve` 命令但在不支持自动启动的环境中 | 终端提示无法自动拉起，并回显手动运行 `python3 server.py` 的指引提示 |
| 6 | `cleanup` 命令传入非白名单分类参数 | 拦截请求并回显错误提示，提示合法的分类参数列表 |
| 7 | 同一域名并发请求密集触发 | 域名限速器自动排队并按间隔加抖动依序发起请求，不造成目标站点高频冲击 |
| 8 | 引擎实例列表为空 | 监控区域展示全局空态引导文案，提示启动新引擎 |
| 9 | 筛选或搜索关键词后无匹配卡片 | 展示「无匹配的引擎实例」并提供「清除筛选条件」按钮，点击后恢复全量展示 |
| 10 | 内存队列引擎处于停止或失败状态 | 卡片明确展示不支持断点续爬文案，不展示续爬操作按钮 |

## 6. 验收标准

1. 用户可启动多个抓取引擎实例，控制台展示等高引擎监控卡片，卡片默认按照运行中置顶、其余按启动时间倒序排列。
2. 列表工具栏支持通过状态按钮组（全部/运行中/已完成/已停止/失败）和关键词输入框进行过滤筛选，筛选按钮带有实时数量徽标；当无匹配项时展示无匹配提示与清除筛选按钮。
3. 处于`running`状态的引擎卡片实时展示脉冲时钟图标与每秒递增的运行时长计时器；处于`finished`、`stopped`、`failed`状态的卡片展示中性时钟图标与基于`ended_at`计算的总耗时。
4. 监控卡片通过四种视觉标签准确区分状态（running高亮与脉冲点、finished绿色、stopped中性灰、failed红色警示），并展示抓取进度条。
5. 仅处于`running`状态的引擎卡片底部提供「停止」操作按钮，点击可单独终止对应engine_id的引擎实例。
6. 针对`stopped`或`failed`状态的卡片，若为SQLite队列则提供「一键续爬」按钮，点击后成功触发断点续爬；若为内存队列则展示不支持断点续爬提示。
7. `finished`状态卡片底部展示已完成无需续爬提示文本。
8. 当运行中引擎数量达到最大并行上限时，再次触发启动能被正确拦截并给出明确上限提示。
9. 针对配置了域名请求间隔的任务，连续请求同一域名时严格满足最小基础间隔与随机抖动延时，且抓取不同域名时并行执行互不阻塞。
10. 看板指标与 status 命令能正确输出所有引擎的聚合统计数据，且每条事件日志均包含对应的 engine_id 标识。
