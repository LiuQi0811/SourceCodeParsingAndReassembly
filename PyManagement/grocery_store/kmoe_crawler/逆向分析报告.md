# Kmoe (kxx.moe) 逆向分析报告

## 一、网站架构分析

### 1.1 基本信息
- **域名**: kxx.moe (kzz.moe, koz.moe 为备用镜像)
- **类型**: Kindle/epub 漫画资源站
- **技术栈**: PHP后端 + 原生JavaScript前端(ES Module)
- **反爬机制**: 请求签名、验证码、登录校验、VIP权限、频率限制

### 1.2 目录结构
```
/                           # 首页（列表第1页）
/l/--/{page}.htm            # 列表分页
/l/{filters}/.../{page}.htm # 筛选列表
/c/{bookid}.htm             # 漫画详情页
/login.php                  # 登录
/dl/{bookid}/{volid}/{line}/{type}/{seq}/0/  # 下载接口
/data_book.php?h={hash}     # 书籍数据API
/data_list.php?k={key}      # 列表数据API
/zzcomm.js?t4               # 核心通信模块
/zzfunc.js?t5               # 业务逻辑模块
```

### 2.2 请求签名机制 (X-KM-FROM头)

**逆向来源**: `/zzcomm.js` 中的 `kb_http_get` / `kb_http_post` 函数

```javascript
// 签名头构造逻辑（逆向还原）
var KB_API_VERSION = 'KMOE/3.0.0';
var KB_FIELD_FROM  = 'X-KM-FROM';

// GET请求签名
xhr.setRequestHeader(KB_FIELD_FROM, 
    KB_API_VERSION + '(' + KM_VIEW + ') GET ' + window.location.pathname);

// POST请求签名
xhr.setRequestHeader(KB_FIELD_FROM, 
    KB_API_VERSION + ' POST ' + window.location.pathname);

// 下载请求签名
xhr.setRequestHeader(KB_FIELD_FROM, 
    KB_API_VERSION + '(' + KM_VIEW + ') DOWN ' + window.location.pathname);

// Fetch下载签名
oHeaders.append(KB_FIELD_FROM, 
    KB_API_VERSION + '(' + KM_VIEW + ') FETCH ' + window.location.pathname);
```

**签名格式**:
```
X-KM-FROM: KMOE/3.0.0(WEB) {METHOD} {PATHNAME}
```

**示例**:
```
X-KM-FROM: KMOE/3.0.0(WEB) GET /c/25519.htm
X-KM-FROM: KMOE/3.0.0(WEB) POST /book_push.php
X-KM-FROM: KMOE/3.0.0(WEB) DOWN /dl/25519/1001/0/2/1/0/
```

### 2.3 下载URL构造

**逆向来源**: 详情页内联 `do_down_batch()` 函数

```javascript
// 下载URL格式（逆向还原）
var str_down_url_prefix = "/dl/" + bookid + "/";

// 单卷下载URL构造
url_down = "/dl/" + bookid + "/" + vol_id + "/" + line + "/" + int_tabdisp 
           + "/" + file_count + "/";

// 参数说明:
// bookid:     漫画ID (如 25519)
// vol_id:     卷ID (如 1001)
// line:       下载线路 (0=普通线1, 1=VIP线2, 9=打包下载)
// int_tabdisp: 文件类型 (0=zip源图, 1=mobi, 2=epub, 3=push)
// file_count: 批量下载序号 (从1开始, 单卷=1)
```

**实际URL示例**:
```
# epub格式 线路1
https://kxx.moe/dl/25519/1001/0/2/1/0/

# mobi格式 线路2(VIP)
https://kxx.moe/dl/25519/1001/1/1/1/0/

# zip源图
https://kxx.moe/dl/25519/1001/0/0/1/0/
```

### 2.4 验证码流程 (captcha_show)

点击下载按钮触发 `captcha_show(url, type)` 函数：

```javascript
// 下载按钮onclick事件
onclick="javascript:captcha_show('/dl/25519/1001/0/2/', 0);"

// 批量下载
onclick="javascript:captcha_show('0', 1);"  // type=1批量
// 打包下载
onclick="javascript:captcha_show(' ', 2);"  // type=2打包
```

验证码流程推断：
1. 前端弹出验证码弹窗（可能包含滑动验证或图片验证码）
2. 用户完成验证后，前端携带验证token请求下载URL
3. 后端验证token后返回真实下载地址或直接设置重定向

## 三、认证与权限体系

### 3.1 用户等级
```javascript
var uin     = "";      // 用户ID (空=未登录)
var ulevel  = parseInt("0");  // 用户等级(0=游客)
var is_vip  = parseInt("0");  // VIP状态
var quota_now = "0";          // 当前剩余额度(M)
```

权限要求：
- **Lv0(游客)**: 仅可浏览，不可下载
- **Lv2**: 可下载普通漫画（需验证Kindle邮箱或手机）
- **Lv3**: 可下载R18漫画
- **Lv5**: 更高权限
- **VIP**: 批量下载、打包下载、VIP线路

### 3.2 登录流程

登录入口: `/login.php`
登录提交: `/login_do.php`

登录需要的字段（待完全逆向）：
- `u`: 用户名
- `p`: 密码（可能经过MD5或其他加密）
- 可能的token/csrf字段

### 3.3 Cookie机制
使用标准PHP Session Cookie (`PHPSESSID`)维持登录状态。

## 四、下载限制

### 4.1 额度系统
- 普通用户有月度流量限制
- VIP每月40G额度
- 下载扣减流量，重复下载（90天内）不重复扣费

### 4.2 频率限制
- 批量下载间隔4秒
```javascript
await moe_msleep(4000);  // 批量下载每本间隔4秒
```

### 4.3 打包下载限制
- 最多20册
- 单包最大2GB
- 打包消耗2倍额度

## 五、反爬策略总结

| 反爬手段 | 实现方式 | 绕过方案 |
|---------|---------|---------|
| 请求签名 | X-KM-FROM头校验UA/版本/路径 | 模拟生成签名头(已逆向) |
| 验证码 | captcha_show弹窗 | 接入打码平台/人工识别 |
| 登录墙 | Session + Cookie | 模拟登录(需账号) |
| VIP权限 | is_vip字段校验 | 需有效VIP账号 |
| 频率限制 | 间隔4秒 + 额度 | 控制请求频率 |
| User-Agent检测 | 浏览器UA校验 | 使用真实浏览器UA |
| Referer校验 | 来源页检查 | 携带正确Referer |
| IP封禁 | 异常访问检测 | 使用代理池/降低频率 |

## 六、待完善的逆向点

### 6.1 密码加密算法
需要分析 `/login_do.php` 的完整请求，确定密码是否加密：
- 可能性1: 明文提交
- 可能性2: MD5哈希
- 可能性3: 前端RSA加密

### 6.2 验证码接口完整流程
需要监控 `captcha_show()` 函数的完整实现（在其他未加载JS文件中）：
```
可能的接口:
- GET /captcha.php?type=down  获取验证码
- POST /captcha_do.php        提交验证码
```

### 6.3 真实下载地址获取
验证码通过后，可能返回：
- JSON格式 `{"downurl": "https://..."}`
- 直接302重定向到CDN地址
- 设置Cookie后授权访问/dl/路径
